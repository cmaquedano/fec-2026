# FEC 2026 — notes for Base44 agents

## Running the app

- Single npm workspace (`backend` + `frontend`). Run everything from the repo root; never `npm install` inside one workspace only — the root lockfile covers both.
- Dev stack: `docker compose -f docker-compose.base44.yml up -d` (container `app`).
  One container runs: `npm ci` → `npm run seed` → `npm run dev` (concurrently: backend `node --watch server.js` on 3001 + Vite on 5173, host port 3000).
- Frontend talks to the backend through the Vite proxy (`/api`, `/uploads` → `localhost:3001`), so dev is single-origin: no CORS involved, and the admin JWT cookie works same-site.
- `frontend/vite.config.ts` needs `host: true` + `allowedHosts: true` — the sandbox proxy sends a rotating external `Host` header; without `allowedHosts: true` Vite returns 403.

## Data / env

- SQLite file at `backend/database/fec2026.db` (WAL mode). `database/db.js` applies `schema.sql` idempotently on every boot; `database/seed.js` creates the admin from `ADMIN_USERNAME`/`ADMIN_PASSWORD` and is a no-op if the user already exists.
- Env vars (`JWT_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`) are delivered via `/run/base44/app.env` (compose `env_file`); they are development placeholders generated by Base44 — the user can replace them in the Secrets dashboard, which recreates the container and re-seeds.
- Uploaded images live in `backend/uploads/{originals,thumbnails}` (created at runtime, not committed).

## Verify it works

- `curl -H "Host: <preview-host>" http://localhost:3000/` → 200
- `curl http://localhost:3000/api/health` (through the proxy) → `{"status":"ONLINE",...}`
- Container healthcheck probes both Vite (5173) and the API (3001) in-container.
